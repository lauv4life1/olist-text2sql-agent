# 模型对比：GLM-4.5-Air vs GLM-4.6V vs DeepSeek

对照条件：同一 prompt（9 个 few-shot + 12 条硬规则 + 输出口径约定，见 `CALIBER.md`）、
同一 Agent 链路（含第 4 层口径断言）、同一评估脚本（`03_agent/evaluate.py`）、
同一基线（`02_sql/baseline_results.json`）、temperature=0、
关闭"深度思考"（GLM 有效，DeepSeek 端点不支持则自动跳过）。

复现命令：

```bash
OPENAI_BASE_URL=https://open.bigmodel.cn/api/paas/v4 OPENAI_MODEL=glm-4.5-air \
  python 03_agent/evaluate.py glm45air
OPENAI_MODEL=glm-4.6v python 03_agent/evaluate.py glm46v
OPENAI_BASE_URL=https://api.deepseek.com OPENAI_MODEL=deepseek-chat \
  python 03_agent/evaluate.py deepseek
```

> 注：`deepseek-chat` 返回的 `model` 字段实为 `deepseek-flash`（该 key 的路由映射）。
> 环境变量优先级高于 `.env`，所以切模型不用改文件。

## 汇总（四个阶段）

| 阶段 | 指标 | GLM-4.5-Air | GLM-4.6V | DeepSeek |
|------|------|-------------|----------|----------|
| ① 初始 | 可执行 / 严格 / 核心 | 90% / 10% / 50% | 90% / 20% / 40% | 100% / 20% / 60% |
| ② 首轮口径治理 | | 100% / 30% / 70% | 90% / 30% / 80% | 100% / 40% / 80% |
| ③ P1–P6 定稿 | | 100% / 50% / 100% | 100% / 50% / 90% | 100% / 60% / 90% |
| ④ **加第 4 层口径断言 + 结构化回灌** | **可执行 / 严格 / 核心 / 口径** | **100% / 60% / 100% / 100%** | **100% / 60% / 100% / 100%** | **100% / 70% / 100% / 100%** |

- **三个模型四项指标全部见顶**：可执行 100%、核心一致 100%、口径通过 100%。
- 严格一致率也顺带上升（50~60% → 60~70%），因为口径修正顺带修掉了部分辅助列的写法差异。
- 相比初始：严格一致率 10~20% → **60~70%**；核心一致率 40~60% → **100%**。

## 阶段 ④ 做了什么（本轮新增）

**1. 新增第 4 层校验 `03_agent/caliber_guard.py`** —— 结果级口径断言，6 条守恒/形状约束：

| 断言 | 口径 | 抓什么 |
|---|---|---|
| 全局总量守恒 | C1 | 单行结果的 `total_orders` / `gmv` 必须等于平台真值 |
| 州维度守恒 | C19 | 各州订单数之和 = 99,440；各州 GMV 之和 = 16,008,872.12 |
| 州输出齐全 | C20 | 出现州列时必须同时有 订单数 / GMV / 平均时长 |
| 分层总体守恒 | C14 | 各档客户数之和 = 96,095（5 × 19,219） |
| 分层列不重复 | C22 | 分层结果里任意两个数值列不得逐行取值相同 |
| 无扇出 | C21 | `JOIN order_payments` 后求 `AVG(TIMESTAMPDIFF)` 必须有订单粒度预聚合 |

**2. 校验反馈结构化回灌** —— 违反断言时把"哪一列、哪一类口径、正确写法"回灌给模型重写，
与静态校验**共用同一份重试预算**（`MAX_RETRIES=2`）。

**3. 评估指标扩展到四个**，新增「口径通过率」与「回灌救回」计数。

## 第 4 层的实战战绩（评估里的「回灌救回」）

| 模型 / 题 | 首轮错在哪 | 断言报了什么 | 结果 |
|---|---|---|---|
| DeepSeek **Q5** | 把 `order_payments` 直接 JOIN 进州粒度 → 时长被扇出加权 | `[C21]` 无订单粒度预聚合 | **第 2 轮改对**（27 州、SP = 41,745 / 8.3 天） |
| GLM-4.5-Air **Q10** | 分层后又 `JOIN per_order` 补"覆盖州数/时长" → `COUNT(*) AS customers` 变成 99,440 | `[C14] 人数偏大` | **第 3 轮改对**（5 × 19,219，逐值等于基线） |
| 两个 GLM **Q10** | "人均单数"写成 `SUM(total_spend)/COUNT(*)`，与人均消费逐行相同 | `[C22] 两列取值完全相同` | 修正为 `AVG(order_count)` → 1.10 / 1.04 / 1.02 / 1.01 / 1.00 |
| GLM-4.6V **Q10** | 用 `customer_unique_id` JOIN `orders.customer_id` → 0 行 | `[C14] 返回 0 行`（空结果不豁免） | 关联键修正 |

## 结论

1. **口径治理仍是最主要的杠杆**：全程**未换主模型**，靠统一口径 + 修正评估指标，
   核心一致率 40~60% → 100%。
2. **软约束有上限，硬断言才是终点**：把扇出风险、总体定义写进 prompt 之后模型照样会犯，
   说明"写进 prompt"只是提高概率；**执行后的守恒断言 + 定向回灌**才把这类错误真正收口。
3. **第 4 层的价值不是"刷分"**：三个模型到阶段 ③ 已经很接近上限，第 4 层带来的
   核心一致率提升有限；它真正的价值是 **① 把偶发错误自动救回（可量化：回灌救回 2/10）**、
   **② 提供一个不依赖人工基线的质量信号（口径通过率）** —— 这在真实业务里才是稀缺品。
4. **严格一致率的剩余差距是有意保留的**：Q2/Q3/Q4/Q9 都是**辅助列差异**
   （基线给明细列、模型按"只输出必需列"精简），按 P1=B 不计为错误。

## 回归验证：压测修复后重跑同一模型

改完高压测试找出的 4 个缺口 + 2 个断言误报（C23 作用域闸门）后，
用**同一个模型、同一批 10 题**重跑确认没有被改坏：

| 指标 | 定稿成绩 | 修复后回归 | 结论 |
|---|---|---|---|
| 可执行率 | 100% | **100%** | 不变 |
| 严格一致率 | 60% | **60%** | 不变 |
| 核心一致率 | 100% | **100%** | 不变 |
| 口径通过率 | 100% | **100%** | 不变 |
| 回灌救回 | 2 题（三模型合计） | 1 题（GLM-4.5-Air Q10） | 量级一致 |

> 说明：这批修复**只影响"部分视图"查询（TopN / 截断）与执行期异常路径**，
> 10 道基准题都不属于这两类，所以分数不变——**这正是期望的结果**：
> 修复效应应该只体现在压测的新场景上，而不是把基准成绩"刷"出新数。
> 同时单题尝试次数明显下降（多数 1 次即过），侧证 C20 的"问题驱动"改法
> 消除了原先"逼模型补未问到的列"的无效重试。

## 诚实记录：仍存在的限制

- 严格一致率未达 100%，且剩余差异全部来自辅助列口径（见上）。
- 断言覆盖"已知错误类型"，不覆盖主观业务口径；新题若形状不同需补断言。
- **守恒断言有作用域前提**（C23）：`LIMIT` / 排名取前 N / 结果被 1000 行截断时主动跳过 ——
  这是压测发现的**两次真实误报**倒逼出来的（误报会把正确答案改坏，比漏报更伤）。
- **"答不了"走显式协议**（`CANNOT_ANSWER`）：识别不了的问题会返回 `unanswerable`，
  不会硬凑一条 SQL。
- LLM 在 `temperature=0` 下仍非完全确定 —— 同一问题跨次运行偶尔给出不同写法，
  单次结果有波动，结论以多轮整体趋势为准（本文件的数据来自**同一次串联运行**，可比性有保证）。
